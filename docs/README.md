# Документація проєкту FitSync AI (Shyft)

> **Практична робота №2:** Бізнес-документ і архітектурна діаграма  
> **Референсний проєкт:** `FitSync AI` / `Shyft`  

У цьому каталозі зібрано повний комплект документації проєкту відповідно до вимог Практичної роботи №2:

## Зміст каталогу `docs/`

1. **[Бізнес-документ (business_doc.md)](./business_doc.md)**
   - Опис системи та вирішення проблеми «gymtimidation».
   - Ролі користувачів: Новачок, Регулярний атлет, Pro-підписник, Контент-адміністратор.
   - 5 ключових Use Cases: Емпатичний онбординг з «Thinking UI», міст «Дім — Зал», динамічна адаптація навантаження («Я втомився», «Тренажер зайнятий»), тривимірний лог підходів та калібрування RPE, запобігання плато (Anti-churn).
   - Функціональні (FR-1...FR-13) та нефункціональні вимоги (NFR-1...NFR-5).
   - Обмеження системи (Non-Goals: без фото, без CRM тренерів, без калорій, алгоритмічний розрахунок навантаження без галюцинацій LLM).
   - Текстове пояснення архітектурних блоків та Mermaid-діаграма системи.

2. **Архітектурні діаграми системи:**
   - **[architecture_diagram.png](./architecture_diagram.png)** — графічне зображення архітектури у високій роздільній здатності (1600x1080) у стилі Liquid Glass Dark Theme.
   - **[architecture_diagram.drawio](./architecture_diagram.drawio)** — вихідний файл діаграми для редагування у [diagrams.net (draw.io)](https://app.diagrams.net/) або в розширенні VSCode.
   - **[architecture_diagram.svg](./architecture_diagram.svg)** — векторний формат діаграми.

3. **[Дорожня карта розробки (roadmap.md)](./roadmap.md)**
   - План робіт на найближчі 4 тижні (Тижні 3–6):
     - **Тиждень 3:** Розробка нових API Endpoints (`/api/dashboard`, `/api/exercises`) та тривимірних JSONB логів.
     - **Тиждень 4:** Базова та соціальна авторизація (GoTrue, JWT Bearer, IUserContext, онбординг «Thinking UI»).
     - **Тиждень 5:** CRUD для тренувальних планів (`/api/plans`) та життєвий цикл активного тренування.
     - **Тиждень 6:** Алгоритми динамічної адаптації («Я втомився», «Тренажер зайнятий»), RPE калібрування та Freemium Guard.
   - Definition of Done (DoD) для завдань.

4. **[Інструкція для командної роботи в Git (GIT_WORKFLOW.md)](./GIT_WORKFLOW.md)**
   - Розподіл ролей між учасниками команди (Lead, Business Analyst, Architect, PM).
   - Покроковий гайд: Fork → Clone → Branch → Commit → Pull Request → Code Review → Merge.
   - Фінальний чек-лист готовності до захисту практичної роботи.
