### Тиждень 5: CRUD для тренувальних планів та активна сесія
*Основна мета: реалізувати повний цикл створення/редагування планів та інтерфейс активного проходження тренування з надійною фіксацією підходів.*

* **Завдання бекенду:**
  - [x] **TASK-501 (CRUD для планів):** Реалізувати ендпоінти в `UserPlanEndpoints.cs`:
    - `POST /api/plans` — створення нового плану або вибір попередньо встановленого «Bridge Plan A».
    - `GET /api/plans/{id}` — отримання деталей плану та списку тренувальних днів.
    - `PUT /api/plans/{id}` — редагування вправ, кількості підходів або черговості.
    - `DELETE /api/plans/{id}` — архівація або видалення плану.

* **Завдання бекенду та алгоритмів адаптації:**
  - [x] **TASK-601 (Адаптація «I’m Tired»):** Розробити алгоритмічний обробник: при отриманні сигналу втоми система автоматично розраховує зниження робочої ваги на 10–15% на наступні сети з округленням до найближчого кроку диска/гантелі (наприклад, 2.5 кг).
  - [x] **TASK-602 (Адаптація «Machine Busy»):** Створити селектор біомеханічних еквівалентів: пошук вправи з ідентичним цільовим м'язом, але без осьового навантаження на хребет (наприклад, заміна присідань зі штангою на жим ногами в тренажері або кубкові присідання з гантеллю).
  - [x] **TASK-603 (RPE Калібрування):** Реалізувати прийом оцінки суб'єктивного навантаження (RPE від 1 до 5) після сесії та формування коефіцієнта перевантаження для наступного тренування (+10%, +5%, норма або Deload).
  - [x] **TASK-604 (Freemium Controller):** Впровадити middleware підрахунку завершених тренувань: блокування перегляду просунутих метрик і виклик Paywall після 8-ї сесії ($10/міс Pro).
* **Завдання мобільного клієнта:**
  - [x] **TASK-605:** Додати кнопки швидкої дії «I’m Tired» та «Machine Busy» на екран активного тренування з показом розмовного вікна підтримки від Nix.
  - [x] **TASK-606:** Реалізувати екран підсумків `WorkoutFinishedScreen` з Lottie-анімацією конфеті, вибором RPE смайликами/шкалою та відображенням підсумкового тоннажу.

  - По завершенню тренування фіксується оцінка RPE, яка відображається у збереженій історії сесій.
  - На 9-му тренуванні користувачу демонструється екран пропозиції підписки.

## 3. Критерії готовності (Definition of Done — DoD)

Кожна задача вважається виконаною лише за умови дотримання таких вимог:
1. **Код та архітектура:**
   - Код написаний згідно з гайдлайнами C# 14 / .NET 10 (file-scoped namespaces, nullable reference types) та TypeScript (strict mode, відсутність `any`).
   - Відсутність заглушок `// TODO` або неповних реалізацій.
   - Дотримано шари FSD 2.1 у мобільному клієнті та патерн Modular Monolith у бекенді.
2. **Тестування:**
   - Нові ендпоінти покриті інтеграційними тестами в проєкті `tests/`.
   - Критичні функції клієнта (розрахунок ваги, парсер темпу) протестовані через Vitest.
3. **Документація:**
   - Оновлено специфікації OpenAPI / Swagger.
   - Всі зміни зафіксовані у відповідних файлах `specs/`.
4. **Git та командний процес:**
   - Робота ведеться через окрему гілку у форку (`fork/feature-name`).
   - Створено Pull Request з описом внесених змін та посиланнями на задачі.
   - Отримано щонайменше 1 схвальне рецензування (Code Review) перед злиттям у гілку `master`.
